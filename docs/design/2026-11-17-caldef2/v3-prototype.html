1 · Changelog from V2

Every issue from the audit, and what replaced it.

Workout · critical

Rest can no longer complete a set

The workout moves through explicit states: set ready, saving, resting, next set ready. "Complete set" exists only while a set is ready. During rest the single primary action is "Skip rest". A pending or refused save is shown on the set itself, in words and shape, not colour alone.

Workout

Weight and reps lead

Fields are 68 px tall and accept typed numbers ("82,5" works), with − and + on either side. The session clock dropped to a small meta line. Exercise names wrap to two lines. "Use" became "Reuse 80 kg × 6". There is one primary button at a time.

Integrity

Double taps and retries can't duplicate

The button locks on the first tap. Each set is saved as "make set N equal to this", so a resend changes the same row. The prototype's demo panel has a double-tap test and keeps a simulated log of every write.

Today

Every number says what it is

"717 kcal eaten of 1,745 · 1,028 kcal left", with the target marked on the bar. Protein in grams of target. The trend in kg with its weekly rate. Meals are full rows: name, calories in their own column, and "Add this meal" in words.

Screens added

The whole app, in both themes

Today with and without a workout, Nutrition with search, amount, review and an empty day, Training home, Library with French and empty searches, Detail with and without media, Progress (weight, strength, cut phase), the grid menu and Settings.

Library · detail

Real catalogue, real search

All 980 exercises and their French aliases are built in. Search follows the app's own rule (accents ignored, every word must match the name or an alias). Chips scroll and are never truncated. Headings state the filter and the count. On the detail page the full name sits above the media, the drawing has more contrast in dark mode, and the credit line is readable. The main action depends on where you came from.

Light mode

L1 by default, L2 as small as possible

L1 "Open porcelain" is the preferred design: a white top with no band. Midnight lives in one place on Today, the balance card, plus the capsule and the actions. L2 is shrunk to the status bar only, a 50 px Midnight cap. The choice between them still waits for the iPhone test.

Capsule · navigation

Resume without overlap

The capsule is a row of the tab bar. It hides while the keyboard is up, keeps the active exercise visible, counts down rest, and shows unsynced sets in amber with words. Returning from the session restores the tab and scroll position you left. The grid menu opens as a sheet over the current tab.

Found on the way

Two small non-visual fixes to schedule

First, Everkinetic's only barbell row is a reverse-grip row, so the hand review rejects it and Barbell Row shows the no-media design. Second, the app's food search does not fold "œ", so "oeuf" cannot match a Ciqual "Œuf …" name in local ranking. It's a one-line fix, to be scheduled separately.

    4 · Workout flow

    Five states, and the rules that keep sets honest.

    stateDiagram-v2
  [*] --> SetReady
  SetReady --> Saving: Complete set (button locks)
  Saving --> Resting: server confirms (Saved)
  Saving --> Resting: no connection (Kept on this phone, retried)
  Saving --> Refused: server refuses
  Refused --> SetReady: Edit and retry / Discard
  Resting --> NextSetReady: timer ends or Skip rest
  NextSetReady --> Saving: Complete set
  NextSetReady --> SessionDone: last set saved
  SessionDone --> [*]: Finish (only when nothing is waiting)

    What each state allows

    • Set ready: edit weight and reps, then "Complete set N · 80 kg × 8". It's the only primary action.
    • Saving: the button shows "Saving set N…" and ignores further taps. The set's row says "Saving".
    • Resting: the timer is the screen and "Skip rest" is the primary action, with ±15 s beside it. Nothing can be completed.
    • Next set ready: the editor returns, prefilled from the plan, with "Reuse 80 kg × 6" from last time.
    • Refused: a red banner says the set was not saved, with "Edit and retry" or "Discard". Nothing moves on silently.

    Mapped to today's code (unchanged)

    • save-queue.ts: one save in flight, latest value per set, failures kept and retried, mirrored to the phone's storage. A refusal is dropped and reported, which matches the Refused state.
    • A set save is an upsert on its position, so a resend can't add a row (invariant 20).
    • Rest and session clocks are now − timestamp, so they are right after the phone is locked (invariant 21).
    • Finish is offered only after the queue has flushed, and "finished" is shown only on the server's answer.
    • Nutrition is not queued offline today: an add with no connection stays in the form, and nothing is written. The prototype shows exactly that.

    5 · Light mode: L1 and L2

    L1 preferred, pending one test on your iPhone.

    L1 uses the default status-bar style: dark time and battery on a light bar. In light mode that is right by definition, because the top is white. The open question is dark mode: whether iOS switches that bar when the phone goes dark, through theme-color with a dark media query. If it doesn't, L2 keeps black-translucent and limits the Midnight band to the status bar's own 50 points.

    How the test runs (about five minutes)

    • Three static pages at /lab/statusbar/a|b|c, with no data and no requests, removed after the test. A is default with theme-color per scheme. B is default alone. C is black-translucent.
    • Add each to the Home Screen, open it, then switch light and dark in Control Centre. Note or screenshot the status bar each time.
    • If A is readable in both modes, the result is L1. If not, the result is L2 as shown here. The app's themeColor becomes per theme either way.
    • This needs your go-ahead, because it is a deployment to production.

    How light mode stays premium without a band

    • One Midnight object per screen at most: Today's balance card and the capsule. Everything else is porcelain and white.
    • Large titles in Geist 600 with tight tracking, and thin tabular figures for numbers.
    • Surfaces have soft shadows tinted toward Midnight rather than grey. Hairlines are cool violet-grey.
    • Purple marks the action (primary buttons, the active tab, "+" and focus) and is never decoration.
    • Champagne appears once, as the personal-record diamond.

    Touch and type

    • The smallest text is 11 px (mono labels), raised from V2's 9 px. Body text is 15 px and figures 34 px or more.
    • Targets are at least 44 points. Steppers are 56 × 68, Complete and Skip rest 58 points tall, the capsule 52.
    • Set state is told three ways: shape (filled disc, hatched, outlined), a word ("Saved", "Waiting to sync", "Not saved", "Planned"), and colour.
    • Reduced motion: sheets fade, nothing pulses, the spinner stops, and no state depends on watching an animation.

    Layout

    • Safe areas: 50 points at the top for the Dynamic Island, and the tab bar and dock pad 26–30 points for the home indicator.
    • The scroll area ends above the tab bar and capsule, so the last row is always reachable (try Nutrition).
    • When the keyboard opens, the capsule and tab bar step aside, and the dock rides above the keyboard.
    • At 360-point widths, names wrap rather than truncate, and the chip rows scroll.
    • Large Dynamic Type is not yet checked. Web text follows the browser zoom, not iOS text size, unless we adopt -apple-system-body. That's an open item.

    7 · Not verified on a physical iPhone

    What only your phone can confirm.

    • Status bar: whether L1's dark-mode status bar follows theme-color in the installed app (the lab test).
    • Keyboard: the decimal keyboard, the comma, and the dock riding above the real keyboard. The grey keyboard in the prototype is a stand-in.
    • Lock and resume: the rest countdown after 30 s locked, and the capsule state on unlock. The logic is today's, but the new screens are untested on a device.
    • Motion: sheet and transition smoothness. View Transitions need Safari 18 or later, and the behaviour without them is an instant switch.
    • One-handed reach on your phone's size, and Complete or Skip under the thumb with sweaty hands.
    • Haptics: none are promised. iOS Safari offers no reliable vibration API.
    • Media: SVG crispness and video playback. No video is mapped yet, and media stays gated on phases 12–13.
